Title

An applied batch file is marked so it can never apply twice

Rule Statement

When the apply-all pass applies a reviewed corrections file, the file is renamed with an applied marker; the same batch can never reach the books twice through the apply-all pass.

Summary

After a corrections file is fully applied in the apply-all pass, it is renamed with an applied marker so a later pass will not pick it up again.

Description

The apply-all pass gathers every pending corrections file next to the ledger data, oldest first, and applies each one. When a file's batch has been applied, the file is renamed with an applied marker (the name grows the marker suffix), so the next apply-all pass no longer sees it as pending. This is the apply-once guarantee: the batch the reviewer prepared reaches the books exactly once through this pass.

def apply_all_pending() -> None:
  """Apply every data/cleanup_fixes* file that has not been applied yet,
  oldest first, and journal the applied files by renaming to *.applied."""
  pending = sorted(
    path for path in data_dir().glob("cleanup_fixes*") if path.suffix in {".json", ".toml"}
  )
  if not pending:
    console.print("[green]No pending fixes files.[/green]")
    return
  for path in pending:
    apply_fixes(path)
    path.rename(path.with_suffix(path.suffix + ".applied"))
