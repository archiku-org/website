A reviewed batch edits plans directly and never journals plan changes

Title

A reviewed batch edits plans directly and never journals plan changes

Rule Statement

Row operations in a reviewed batch that act on expectations — removing one or adding one — edit the register of plans directly and produce no journaled event; only acts on committed rows land as journal events.

Summary

When a batch removes or adds an expectation, the register of plans is rewritten in place with no recorded event; recorded money, by contrast, always changes through a journal event.

Description

A batch's removal operation looks the same for a recorded row and a planned one — both are addressed by the e-series id a planned entry carries — but the handling splits by where the row lives. Naming a committed row journals a removal event carrying the row's full picture; naming an expectation simply strikes it from the register of plans, with nothing recorded. Likewise a batch's expected-row addition writes the new plan straight into the register and journals nothing. This keeps the journal a history of actual money only: plans are hypotheses that may be created and withdrawn without leaving a recorded trail, and every event in the journal is a change that happened to real recorded money.

def add_expected_row_from_fix(fix: dict) -> str:
  """(Re-)create a one-off expected entry from a fix file's own fields
  (fix-file op add_expected_row). Returns the new entry's id."""
  entry = Transaction(
    id=_next_id(load_expected()),
    date=fix["date"],
    description=fix["description"],
    category_raw=fix["category"],
    category=fix["category"],
    subcategory_raw="",
    subcategory="",
    amount_eur=fix["amount_eur"],
    status=STATUS_EXPECTED,
    linked_id="",
    source_line=fix.get("source_line", 0),
    note=fix.get("note", ""),
  )
  expected = load_expected()
  expected.append(entry)
  save_expected(expected)
  return entry.id
