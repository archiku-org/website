A real booking inside the window supersedes the projected instance

Title

A real booking inside the window supersedes the projected instance

Rule Statement

When the rule's due date arrives, a committed transaction with the same category and the same amount (within a cent) dated within five days of the due date stands in for the projected instance, which the forecast then drops.

Summary

Superseding — the forecast shows the rule instance until actual money with matching category, amount and timing covers it; then the projection yields to the real row.

Description

The forecast never double-counts a bill that was actually paid. For each projected instance the planner looks at the committed history around the due date: if a real transaction in the same category carries the same amount (to within a cent) and sits within five days either side of the due date in the same year, the projection skips the instance and the real booking stands alone in the view. This is what makes the rules a forecast layer rather than a duplicate ledger: the moment real money shows up, the planned row retires for that period without anyone closing it. Rules whose pattern drifts (a real payment at a different amount) are handled by the approval process's exception recording, not by this matching.

def _covers(occurrence: date, rule: Recurrence, transactions: list[Transaction]) -> bool:
  """True when a real transaction covers this rule instance's period."""
  window_lo = occurrence - timedelta(days=DAY_WINDOW)
  window_hi = occurrence + timedelta(days=DAY_WINDOW)
  for t in transactions:
    if not t.date or not t.date.startswith(str(occurrence.year)):
      continue
    t_date = date.fromisoformat(t.date)
    if not (window_lo <= t_date <= window_hi):
      continue
    if t.category != rule.category:
      continue
    if t.amount_eur is None or abs(t.amount_eur - rule.amount) > AMOUNT_TOLERANCE:
      continue
    return True
  return False
