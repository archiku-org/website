Confirm never adjusts values

Title

Confirm never adjusts values

Non-Goal Statement

The confirm command deliberately offers no way to change what an entry says — date, description, category and amount are only adjustable through the edit flow, never at confirmation time.

Summary

Confirm and edit are separate moments by design; every refusal message points to edit rather than offering a correction path of its own.

Description

The command's help text states the division of labor explicitly: confirm what landed as-is, adjust first with the edit command. The only value confirm ever changes is the date of a future-dated rule instance in the interactive path — shifted down to today, never ahead. Everything else stays exactly as registered or as the rule carries it.

The boundary holds across all three branches and is visible in the refusal messages, which name the edit flow rather than offering a prompt. This is what keeps confirm fast (zero prompts on the landed path) and the books honest (nothing enters history that was not stated first).
