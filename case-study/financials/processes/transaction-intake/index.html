Transaction intake

Process Name

Transaction intake

Title

Transaction intake

Summary

The owner records a money movement in the ledger — by shorthand, fully flagged, or interactively — landing it either as a committed actual row in the event journal or, when dated in the future, in the expected register.

Description

The owner records a money movement the moment it happens — by typed flags, by a one-line shorthand phrase, or by answering the questions with nothing assumed. What the owner did not state is asked; what the owner states is checked against the house rules before anything is stored.

The date decides where the entry lands. A movement dated in the future has not happened, so it is kept in the expected register — no saldo, no ledger influence — until a later decision confirms it into the real books. A today-or-past movement is saved as one recorded event (append-only, carrying its own content-derived identity), the ledger is brought up to date immediately, the checkpoint is persisted atomically, and the owner sees the saved row with its fresh checking and savings saldos.

Refusals are part of the story: an unapproved category, a zero amount, an unreadable date, an empty description, or a date the balance chain cannot start from — each stops the save with a stated reason and nothing stored. During interactive capture the owner must confirm the projected saldo (three tries) before a real save; the interactive abort leaves nothing stored. The preview path shows what would be stored without storing it.

Trigger

A payment or receipt must be recorded — the owner captures the money movement when it happens. Surface: the financials add command (flags, shorthand, or interactive).

BPMN XML

process "Owner"
  start "A payment or receipt needs recording"
  user "State the movement"
  receive "Hear the outcome"
  end "The movement is in the books"

process "Financials"
  start "Capture request arrives"
  service "Understand the stated entry"
  exclusive "Dated after today and fully stated?"
    if "Yes" then
      goto "Keep the entry as an expectation in the expected register"
    else "No"
  exclusive "Anything still missing?"
    if "Yes" then
      user "Ask for the missing pieces and confirm the projected saldo"
      exclusive "Owner confirmed the saldo inside three tries?"
        if "No" then
          task "Store nothing and tell the owner why"
          end "Capture abandoned"
        else "Yes"
      exclusive "The completed date is after today?"
        if "Yes" then
          goto "Keep the entry as an expectation in the expected register"
        else "No"
    else "No"
  service "Check the entry against the house rules"
  exclusive "Does the entry pass?"
    if "No" then
      task "Refuse the entry with the stated reason"
      end "Entry refused"
    else "Yes"
  exclusive "Preview only?"
    if "Yes" then
      task "Show what would be stored and store nothing"
      end "Preview shown"
    else "No"
  service "Record the movement as a stored event"
  service "Bring the books up to date with the new movement"
  task "Report the saved row and its new saldos"
  end "Movement stored"
  task "Keep the entry as an expectation in the expected register"
  task "Report the entry kept for the future"
  end "Future recorded"
