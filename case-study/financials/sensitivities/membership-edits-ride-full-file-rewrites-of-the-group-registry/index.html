Membership edits ride full-file rewrites of the group registry

Title

Membership edits ride full-file rewrites of the group registry

Sensitivity Statement

Every membership change rewrites the whole group registry file, so a save racing another save — or crashing mid-write — can lose the other change; the registry has no journalling or merging.

Summary

The group registry is saved as one whole on every edit; concurrent or interrupted saves are the fragility to handle with care, unlike the append-only journal that protects real money records.

Description

Groups deliberately sit outside the journaled money path (that journal protects committed money; groups are forecast-input metadata), and the price is that the registry is rewritten as a file on every create, add, remove, edit and confirm re-point. Two saves in quick succession — for example a confirmation walking its members while the owner edits the group — are last-writer-wins on the whole list. The confirm flow works around this by re-reading the registry fresh before every save, a pattern any future writer must copy.

def load_groups(path: Path | None = None) -> list[Group]:
  path = path or _groups_file()
  if not path.exists():
    return []
  with open(path, encoding="utf-8") as fh:
    rows = json.load(fh)
  return [Group(**row) for row in rows]


def save_groups(groups: list[Group], path: Path | None = None) -> None:
  path = path or _groups_file()
  path.parent.mkdir(parents=True, exist_ok=True)
  with open(path, "w", encoding="utf-8") as fh:
    json.dump([asdict(g) for g in groups], fh, ensure_ascii=False, indent=2)
    fh.write("\n")
