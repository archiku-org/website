Introduction

A personal double-entry ledger with declared intentions — an audit-first household money book where every recorded change appends to one unbroken history and nothing is ever rewritten in place.

Findings a manager should act on:

  1. The books are tamper-evident by construction: every save, correction and removal is an append-only event identified by its own content (the write core), and a deletion carries the removed row's complete picture, verified against the live row before it applies (the pre-image concept). Trust these books and treat any content-mismatch boot refusal as an incident.

  2. Reviewed correction batches are not atomic: a refused entry stops the run with earlier entries already applied and journaled, and recovery is human (the no-rollback boundary). Worse, only the apply-all pass marks a consumed batch file so it cannot apply twice — a single-file application leaves it pending and re-applies the leading entries on every retry (the marking rule). Decide whether that asymmetry is grace or a defect.

  3. Surfaces speak two languages: batch corrections answer in English while every interactive surface answers in Dutch (the batch process). Small, user-facing, worth a decision.

  4. One boundary question is open for the business: an expectation reserved with a deliberate zero amount can confirm into a zero-amount committed row, because confirm blesses values as-is (the correction process). Whether that is gap or grace is not decodable from the behaviour alone — it needs a business ruling.

Next step: read the product summary for the capability-by-capability walk, then the archetype mapping for the kind of application this is — and bring the four findings above to the owners of the books.

Verification status: the vault's objection census holds zero entries — no objections have been captured against this analysis, so these findings stand unchallenged but also unverified by that signal.
